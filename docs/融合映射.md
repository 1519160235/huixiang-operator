# 融合映射

> 四源合成一个插件。这张表是融合的权威依据：逐条到文件、到函数，写清「落入哪一块、怎么搬」。
> 移植方式三档：**直接搬**（几乎原样可用）/ **需改造**（方向对，要改口径或接口）/ **仅参考**（只取思路或口径，不搬代码）。
> 三路深读结论直接落表，不重新推导。

## 六块简称

| 块 | 简称 | 管什么 |
|---|---|---|
| 接入层 | 接入 | 登录、收@回复、主动浏览、分区动态拉取 |
| 感知层 | 感知 | 作息情绪、热门有奖话题 |
| 创作层 | 创作 | 内容生成、中文口语、AI 配图、感想总结 |
| 护栏层 | 护栏 | 额度、去重、限流、去 AI 味、熔断 |
| 发布层 | 发布 | 直连签名、发帖、评论、图床、回读核验 |
| 状态存储 | 存储 | 动作状态、额度、去重、游标、持久化 |

## 搬运顺序提示

- 先搬源②（vendor 直连客户端 + 登录），它是一次发帖闭环的地基。
- 护栏四件套（源① 的 gap/aiflavor/captcha/ratelimit）纯算法，可随护栏层一起直译，不依赖网络。
- 源③的 `image_generation.py` 独立可搬，配图能力早接早验证。
- 源④骨架负责兜底：六块接口、配置模型、状态机都从它扩，不推倒重写。
