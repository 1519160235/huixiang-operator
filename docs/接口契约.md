# 接口契约

> **骨架阶段未实现，仅作实现依据。** 下面是从四源深读结论整理出的中文对照表。现在没有签名客户端、没有凭据、没有发布层，不连真实 API。将来写发布层时逐条对照，不靠猜。
> 本表已按四源融合结论修正旧文档错误（`topicIds` 类型、图床尺寸、签名分流）。

## 一、分区与分类

| 项 | 口径 | 错了会怎样 |
|---|---|---|
| 图文帖 `link_tag` | `27` | 给错值发不出去 |
| 动态（无图）`link_tag` | `28` | 纯文字帖该用这个 |
| 文章 `link_tag` | `11` | 长文走 HTML 正文 |
| `21` | 不是合法发帖分类 | 小黑盒判「错误的动态分区」直接拒 |
| `topicIds` | 逗号分隔的数字字符串，如 `"12,34,56"`，**不是 int 数组** | 传数组或单个 int 会解析失败 |
| 活动话题 | 走 `hashtags` 参数，传准确名称；有奖励活动话题优先 | 名字过期就白丢一次曝光 |
| 话题数量 | 最多 5 个 | 超过 5 个可能被拒 |

## 二、字段口径

| 字段 | 口径 | 错了会怎样 |
|---|---|---|
| 推荐流帖子 ID | `postId`，不是 `id` | 取到空值，后面全链路断 |
| 完整正文 | `link.text`，块序列化 JSON | `description` 只是摘要，拿摘要改正文会把内容改没 |
| 图片 | 在正文 `text` 的 `img` 块里 | 当成单独字段去找会找不到 |
| 分区解析 | 名称按准确匹配换成数字 topic ID | 名字差一个空格就解析不到 |
| 标题读回 | 可能有短暂延迟 | 别因此重复提交 |

## 三、签名与域名

| 项 | 口径 |
|---|---|
| 读请求（GET） | 走 `api.xiaoheihe.cn`，签名用 `generate_hkey(path, stamp, nonce)` |
| 写请求（POST） | 用 `comment_query`，hkey 用 `stamp+1` 计算 |
| 写域名 | workshopapi 域名 |
| 读域名 | api 域名 |
| hkey | 每次请求按路径重新算，不能把一条请求的签名复用到别的路径 |
| 客户端契约 | 不等于稳定公开 API，平台可能改；改了先改本表再改代码 |

关键区分：读和写的 hkey 算法口径不同。读是 `generate_hkey(path, stamp, nonce)`；写是 `comment_query` 那套，hkey 用 `stamp+1`。别把两套混用。

## 四、图床 COS 三步

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | `info/v2` | 传 `file_infos`、`scope=bbs`、`need_cache`，拿 bucket、region、对象 key |
| 2 | `token/v2` | 传 `bucket`、`keys`、`mimetypes`、`is_multipart_upload`；临时凭据只在内存里用，不写文件、不写接口结果 |
| 3 | `PUT` → `callback/v2` | 先 PUT 到 COS，再查 `callback/v2` 的 `is_finished=true`，读 `preview_urls` / `thumbs` |

图片上限：

| 项 | 上限 |
|---|---|
| 单图大小 | ≤ 5 MB（旧文档写的 5 GiB 是错的） |
| 单图像素 | ≤ 2000 万像素 |
| 单帖图数 | 最多 6 张 |

平台可能转换 CDN 地址和 HTML 属性顺序，回读按同一资源标识与正文语义核验，不做 URL 字符串相等比较。

## 五、发帖与回读核验

| 项 | 口径 |
|---|---|
| 验证发帖 | 用 `get_post(postId)` / `fetch_thread_context` 回读 |
| `search_posts` | 不索引新帖。搜不到不能当作「没发出去」 |
| 接受但回读失败 | 记 `accepted=true, verified=false` |
| 没有服务端响应 | 结果未知，不自动重发 |
| 图片核验 | 只有附图真成功才要求回读含图；生图或上传失败就降级纯文字 |

## 六、评论与楼中楼

| 项 | 口径 |
|---|---|
| 回楼中楼 | 必须带 `rootId`，取通知的 `rootCommentId` |
| 顶层评论 | `reply_id` / `root_id` 两个都是 `-1` |
| 不带或带错 `rootId` | 上游返回 `error root` |
| 楼中楼分页 | 用 `root_comment_id` / `lastval`，`lastval` 取最后一条已读评论的 ID |

## 七、登录凭据

四个必需字段，缺一不可：

| 字段 |
|---|
| `user_pkey` |
| `user_heybox_id` |
| `heybox_id` |
| `x_xhh_tokenid` |

二维码有效期约 60~120 秒，过期重新触发即可。凭据只放数据目录，不写日志、不进 Git。

## 八、分区动态

| 项 | 口径 |
|---|---|
| 接口 | `TOPIC_INDEX` → `parse_catalog`，或 `searchEditorTopics` |
| 拉取方式 | 运行时动态拉取，定时刷新保证最新，不硬编码 |
| 签名 | 拉目录要带 hkey，不能用纯 cookie 手拼 URL |
| 失败处理 | 解析不到准确名称就跳过本轮，不往不确定的分区发 |
| 特殊参数 | 目录接口不带规定参数会报「请升级至最新版本」 |

## 九、护栏阈值

| 项 | 阈值 |
|---|---|
| 去 AI 味（评论） | 打分达 45 即拦下重写 |
| 去 AI 味（正文） | 打分达 60 即拦下重写 |
| 发帖间隔 | 30 分钟 |
| 验证码冷却 | 5 分钟 |
| 限流 | 单请求 5 秒 / 每小时 30 次 |

## 十、感想总结发帖口径

| 项 | 口径 |
|---|---|
| 触发 | 刷完小黑盒后，对刷过内容做总结 |
| 字数 | 200–400 字 |
| 段数 | 2–4 段 |
| 用途 | 作为一篇帖子发出 |

字段以本表为准。平台改了，先改本表，再改代码。
