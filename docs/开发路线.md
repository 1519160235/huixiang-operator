# 开发路线

分七阶段。每阶段只写三件事：产出 / 验收方式 / 依赖上一阶段什么。没验收不进下一阶段。骨架阶段不接真实 API、不启用。

## 阶段 1 · 融合骨架（已完成，2026-11-04）

- 产出：四源合成六块架构定稿。交付 `docs/融合映射.md`（四源→六块→函数级搬运方式）、六块 `DESIGN.md`、修正后的 `docs/接口契约.md`、扩充的 `docs/避坑清单.md`、10 配置段的 `docs/配置说明.md`、七阶段路线、`README.md`、`CHANGELOG.md`。
- 验收方式：`docs/融合映射.md` 四源每个文件都有搬运方式；`docs/接口契约.md` 的 `topicIds` 已是数字字符串、图床尺寸已是 5 MB；六块架构的「不负责什么」每块都写全；`docs/开发路线.md` 七阶段「依赖上一阶段」能从头串到尾。
- 依赖上一阶段什么：无，这是融合起点。

## 阶段 2 · 搬 vendor 直连客户端 + 登录（已完成，2026-11-04）

- 产出：搬入源② `vendor/`（request_signing、api_client、security、endpoints、parsers、rate_limiter）、`comment_signing.py`、`auth.py`；扫码登录拿齐四字段凭据放数据目录，二维码过期能重新生成。不写任何真实数据。
- 验收方式：用合成凭据跑签名自查，不连真实账号；四字段齐全才继续；读走 `generate_hkey(path, stamp, nonce)`、写走 `comment_query` 且 hkey 用 `stamp+1`；日志里没有凭据明文。
- 依赖上一阶段什么：`docs/接口契约.md` 的签名、域名、凭据四条，加 `docs/避坑清单.md` 第 8、11、12、18 条。

## 阶段 3 · 最小闭环（代码落地完成，2026-11-04；真发待服务器人工盯发）

登录 → 选分区 → 生成 → 配图 → 发一篇 → 回读核验。

- 产出：六块代码全部落地——`media_upload.py`（图床三步）、`community_client.py`（发帖/发文章/回读）、`state.py`（JSON 存储 + 额度分桶 + 去重 + 幂等 + 熔断）、`layers/create.py`（口语清洗 + AI 味打分直译 + 降级）、`layers/guard.py`（六道闸）、`layers/publish.py`（发帖/图床/回读 + dry_run）、`layers/inbound.py`（分区目录 + 浏览）、`layers/sense.py`（生活轨迹 + 能否开口）、`plugin.py`（run_once 编排）。AI 味阈值统一 0–100。
- 验收方式（已完成部分）：纯逻辑 47 项测试全过；连打十次演练额度不变（real 桶为 0）；topicIds 是数字字符串、最多 5 个；不刷游戏社区（分区运行时动态拉取，不写死）；不用 search_posts 当判据（回读走 fetch_thread_context）。
- 验收方式（待服务器）：人工盯着发一篇、回读 verified=true、标题正文图对得上。
- 依赖上一阶段什么：阶段 2 的签名与登录，加 `docs/接口契约.md` 全部字段、`docs/避坑清单.md` 第 1~7、17、19 条。

## 阶段 4 · 评论 / 浏览 / 互动（代码落地完成，2026-11-04）

- 产出：主评论、楼中楼（带 rootId）、通知路径（收@回复自动回）；自动浏览（默认不限制分区、可勾选浏览分区）；互动评论（勾选开启，评论+间隔可配）；分区定时刷新。
  - 代码落地：`state.py` 通知去重、`layers/inbound.py` 通知拉取 + 分区过滤 + 定时刷新、`layers/publish.py` 评论 / 楼中楼 / 通知回复、`layers/guard.py` 评论闸门、`layers/interact.py` 互动编排、`plugin.py` 命令与编排。
- 验收方式（已完成）：67 项测试全过（新增 20 项阶段 4 测试）；带 `rootId` 回楼中楼（parent≠root）；同一通知不重复处理；浏览分区勾选后只刷勾选分区；分区列表定时刷新。
- 验收方式（待服务器）：真实评论 / 回复 / 通知响应需人工在服务器点头。
- 依赖上一阶段什么：阶段 3 的回读核验与去重键，加 `docs/避坑清单.md` 第 7、9 条。

## 阶段 5 · 感想总结发帖（代码落地完成，2026-11-04）

- 产出：刷完小黑盒后对刷过内容总结并发帖；200–400 字、2–4 段；复用创作层中文口语与护栏层。
  - 代码落地：`state.py` 浏览摘要存储、`layers/create.py` 字数段数收敛 + 素材整理 + 总结生成、`layers/summarize.py` 触发判定 + 编排、`plugin.py` `/回响总结`。
- 验收方式（已完成）：97 项测试全过（新增 30 项）；字数落在 200–400、段数 2–4（代码侧收敛，不靠提示词）；触发判定 count/time/both 三分支正确；AI 味按正文 60 阈值过闸。
- 验收方式（待服务器）：真实发一篇总结、回读 `verified=true`。
- 依赖上一阶段什么：阶段 4 的浏览数据源，加阶段 3 的发帖闭环。

## 阶段 6 · 自动运营 Worker 与额度（代码落地完成，2026-11-04）

- 产出：后台 Worker、作息联动（睡觉小睡停发）、每日额度与冷却、默认演练、演练与真实额度隔离；操作记录 WebUI。
  - 代码落地：`worker.py` 后台循环（浏览→互动→总结）、`state.ActionLogStore` 操作记录、`sense` 作息判停 + 发帖时段、`guard.check_time_window` 闸门、`plugin` 生命周期与 `/回响记录`。
- 验收方式（已完成）：146 项测试全过（新增 28 项）；`dry_run` 默认开；额度只被真实发送消耗；作息判停生效；限流 5 秒 / 30 次每小时生效；验证码熔断 5 分钟冷却生效；单轮异常不打死 worker。
- 验收方式（待服务器）：真实模式挂后台跑，观察一整天的额度与操作记录。
- 依赖上一阶段什么：阶段 3、4、5 的动作全部人工验收过，才交给自动跑。

## 阶段 7 · 外围联动（代码落地完成，2026-11-04）

- 产出：语音播报、QQ 空间、日记等可选出口；关掉任一个不影响发帖闭环。
  - 代码落地：`layers/links.py` 三出口（走 `ctx.api.call`）、开关短路、失败降级、`plugin._announce` 旁路调用。
- 验收方式（已完成）：146 项测试全过（新增 16 项）；逐个卸掉联动（含全关）发帖闭环仍通；文案全中文；页面分区下拉联动话题仍正常。
- 验收方式（待服务器）：真实接上语音 / QQ 空间 / 日记插件后逐个开、逐个关。
- 依赖上一阶段什么：阶段 6 的稳定 Worker，且与发帖闭环解耦。

## 收尾规矩

- 每个阶段完工，按「改了什么 / 为什么 / 怎么验证」往 `CHANGELOG.md` 追加一条。
- 要启用、要切自动、要真发，都由人点头，不自动放行。
- 平台字段变了，先改 `docs/接口契约.md` 和 `docs/避坑清单.md`，再改代码。
