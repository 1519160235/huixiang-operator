# 回响 · 配置说明

> 中文名：回响 ｜ 插件 ID：`local.huixiang-operator` ｜ 仓库：`1519160235/huixiang-operator`
>
> 本版是**四源融合后的设计与骨架**：代码是接口定义和 TODO 占位，不连真实小黑盒接口、不联网、不部署。
> 共 **12 个业务段**（外加末尾的 `[plugin]` 段，合计 13 段）。字段名与 `config_model.py` 严格对齐，配置页字段标签全中文。

## 一、先别启用

- 默认 `basic.enabled = false`、`basic.mode = "dry_run"`：新插件先不启用、先演练。
- 确认配置无误后，再把 `enabled` 改为 `true`、`mode` 改为 `auto`。
- 首次安装带依赖的插件可能因握手超时而失败，**再启动一次 MaiBot 即可**，不是配置错误。

## 二、`[plugin]` 必须放在文件最后（重要）

- TOML 规则：段头之后的所有裸键都归属该段。`[plugin]` 放在开头，后面的字段会被错误归入 `[plugin]`，框架读不到配置、全部退回默认值。
- 顺序：各业务段 → **`[plugin]`（最后，仅 `config_version`）**。
- `[plugin]` 之后不要再写任何裸键。`[plugin].config_version` 必须有。

## 三、配置分段总览（11 段 + [plugin]）

| 段 | 作用 |
|---|---|
| `[basic]` | 启用、运行模式、资料档 |
| `[login]` | 扫码登录（凭证不进 config） |
| `[browse]` | 自动浏览 + 分区动态拉取 / 定时刷新 |
| `[interact]` | 互动评论 + @/回复响应 |
| `[publish]` | 自助发帖 + 话题联动 |
| `[summarize]` | 感想总结发帖 |
| `[image]` | AI 配图（1~N 张） |
| `[create]` | 创作语气与排版 |
| `[sense]` | 生活感知 |
| `[guard]` | 护栏与额度 |
| `[links]` | 外围联动 |
| `[plugin]` | 元信息（仅 config_version，放最后） |

## 四、逐段字段与默认值

### `[basic]` 基础

| 字段 | 说明 | 默认 |
|---|---|---|
| `enabled` | 是否启用插件 | `false` |
| `mode` | 运行模式：`dry_run` 演练 / `auto` 自动 | `"dry_run"` |
| `profile_id` | 资料档 id（骨架占位） | `""` |

### `[login]` 登录

| 字段 | 说明 | 默认 |
|---|---|---|
| `auto_login` | 是否自动尝试登录 | `false` |

四个凭据字段（`user_pkey`、`user_heybox_id`、`heybox_id`、`x_xhh_tokenid`）由登录流程写入数据目录，不落在配置里。

### `[browse]` 自动浏览

| 字段 | 说明 | 默认 |
|---|---|---|
| `enabled` | 是否开启自动浏览 | `true` |

| `selected_partitions` | 指定分区清单（`selected` 时生效，运行时动态拉取） | `[]` |
| `refresh_partitions_interval_minutes` | 分区列表定时重测间隔（分钟），保证最新 | `360` |
| `browse_interval_seconds` | 浏览间隔（秒） | `300` |
| `posts_per_round` | 每轮浏览帖子数 | `10` |
| `follow_partition_feed` | 是否跟随分区动态流 | `false` |

### `[interact]` 互动评论

| 字段 | 说明 | 默认 |
|---|---|---|
| `comment_enabled` | 是否开启评论 | `true` |
| `comment_interval_seconds` | 评论间隔（秒） | `600` |
| `max_comments_per_round` | 每轮互动最多评论帖子数 | `3` |
| `reply_mentions` | 是否响应 @ 通知 | `true` |
| `reply_replies` | 是否响应回复通知 | `true` |

### `[publish]` 自助发帖

| 字段 | 说明 | 默认 |
|---|---|---|
| `default_partition` | 默认分区（下拉，候选运行时拉取） | `""` |
| `linked_topics_enabled` | 是否自动多挂几个相关分区 | `true` |
| `max_topics` | 单帖最多挂几个分区（`topics`） | `5` |
| `community_allowlist` | 固定要挂的分区名 | `[]` |
| `custom_topics` | 同上（老字段，保留兼容） | `[]` |
| `hashtags_enabled` | 是否自动带话题标签（`hashtags`） | `true` |
| `max_hashtags` | 单帖最多带几个话题 | `5` |
| `custom_hashtags` | 固定要带的话题名 | `[]` |
| `readback_verify` | 发帖后回读核验是否成功 | `true` |

> **分区（`topics`）和话题（`hashtags`）不是一回事**：分区是「发到哪个板块」，
> 话题是帖子上的 `#标签`。真实帖子的结构是
> `topics=[{"topic_id":806933,"name":"AI"}]` + `hashtags=[{"name":"deepseek","hashtag_id":689666}]`。
> 话题没有公开列表接口，插件从真实帖子里采样成池子（`data/hashtags.json`），
> 发帖时按正文匹配挑，匹配不上就不带。

### `[summarize]` 发帖

| 字段 | 说明 | 默认 |
|---|---|---|
| `enabled` | 是否允许它自己发帖 | `true` |

**篇幅不设限**：想写一句就一句，想写十段就十段，长度由内容决定，不再有字数 / 段数上下限，
也不会因为「字数不够」重试凑字。

**时段不设限**：什么时候发由它自己判断（先问「想发吗」，不想发就这一轮不发），
不再有「发帖时段」配置。防失控只剩两道闸：`[guard].daily_quota_post` 每日上限，
以及 `[sense]` 的生活状态（睡觉 / 累垮不发）。

`trigger_by` / `count_threshold` / `time_hours` / `min_chars` / `max_chars` /
`min_paragraphs` / `max_paragraphs` 均已停用，配置页上不再显示。

## 五、分区与话题联动

- 社区（分区）必须是下拉、不能自由填；选完分区后，话题下拉才给出该分区推荐话题；有奖励活动话题优先。
- 话题同样用下拉；另留「自定义话题」兜底。单帖最多 `publish.max_topics`（默认 5）个话题。
- 分区与话题运行时动态拉取、定时刷新（`browse.refresh_partitions_interval_minutes`），不硬编码在代码里（类型用 `str` / `list[str]`，绝不硬编码静态 `Literal`）。

## 六、演练绝不占用真实额度（重要）

- `guard.dry_run_no_quota_cost = true` 必须保持；`basic.mode = "dry_run"` 是默认。
- 历史问题：MCP 的 dryRun 分支同样写入额度文件，演练三次把自己挡在门外。
- 演练分支约定：不写额度消耗、不累加发帖间隔计数、不产生真实发帖动作；额度与间隔只在自动模式、真实动作成功回读后才计。

## 七、WebUI 工作台

- `webui/控制台.html` 是浅色中文工作台骨架，含登录状态、今日额度、分区与话题联动下拉、浏览与互动开关、操作记录、演练开关，静态占位、注明「骨架阶段，数据未接」。
- WebUI 查询接口：`get_overview`（总览）、`get_quota`（额度）、`get_settings`（设置）、`get_action_log`（操作记录）。
- WebUI 动作接口：`dry_run_once`（演练试发）、`reset_circuit_breaker`（解熔断）、`refresh_partitions`（刷分区）、`interact_once`（演练互动）、`summary_once`（演练总结）。
- 路径末尾不带斜杠，只收 POST，`kind` 只能是 `queries` / `actions`（已知问题清单第 16 条）。

## 七之二、后台 Worker 与作息

- Worker 间隔取 `[browse].browse_interval_seconds`（默认 300 秒），每轮依次跑「浏览 → 互动 → 总结」。
- 运行模式只由 `[basic]` 决定：`enabled=true` **且** `mode=auto` 才是真实，其余一律演练——避免误发。
- 作息联动：`[sense].pause_on_sleep=true` 时，作息为深夜 / 睡觉 / 睡眠 / 凌晨 / 小睡 / 午睡 / 打盹 / 刚睡下 时整轮跳过。
- 发帖不限时段：`[publish]` 里不再有时段配置，任何时间都可以发。
  真正决定发不发的是「想发吗」那一步（`create.decide_want_to_post`）和生活状态；
  每日条数由 `[guard].daily_quota_post` 兜底。
- 操作记录落 `数据目录/action_log.json`，只留最近 500 条，`/回响记录` 与 WebUI `get_action_log` 可查。
